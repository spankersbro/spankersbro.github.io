Featured build

Every end-to-end test worker gets its own database

The browser tests shared one database. So every spec carried cleanup code, unique names and rules about which seed data it could touch, and specs could not run fully in parallel.

  1. One database per worker, reset before every test. Triggers note which tables a test wrote, and only those are copied back from the seed: 26 to 44 ms per test on average.
  2. The specs lost their isolation code. No cleanup, no restores, no unique names, and full parallel runs are on. The change removed more lines than it added: 4,887 in, 5,360 out.
  3. Review knows the new rules. The code-review instructions check new specs against one database per worker, so the old patterns do not come back.

It was the last step of a month spent on the suite's reliability. The writeup tells the whole story, including the flaky tests the agent wrote itself.

Featured build

A runtime upgrade that would have moved amounts by a cent

Security support for the old PHP version ends on 31 December 2026, so the upgrade to 8.5 had to land before my last day. The risk was not the syntax. From PHP 8.4, a computed half cent rounds down: 2.50 × 1.19 = 2.975 gives 2.97.

  1. Keep the old result where money is involved. All 206 rounding calls go through one helper that returns what the old version returned.
  2. A test fails on any new native rounding call. On the day of the merge it caught two calls that other pull requests had added in the meantime. The fix was two lines.
  3. Deprecations are guarded the same way. A second test fails on any new call that the new version deprecates.

448 files changed, in one reviewed pull request.

Personal AI Research

OSINT Real-Time Tracker — multilingual conflict monitoring, built solo with Gemini

A maps-based dashboard that monitors global conflict events close to real time. It takes open-source reports — social posts, wire dispatches, radio transcripts — in whatever language they were written, and turns them into structured, geolocated, credibility-scored events a researcher can actually use.

  1. Multilingual intake, no separate translation step. Signed-in users paste raw source text in Ukrainian, Arabic, French, Hebrew, or English and Gemini handles extraction directly — entities, location, and language nuance in one pass, not a translate-then-analyze pipeline.
  2. NLP-based geolocation. Gemini resolves place names and context clues into exact coordinates, with the reasoning behind each resolution shown, not just a pin dropped on a map.
  3. Sentiment and tension scoring beyond positive/negative. Each report gets a sentiment score, a 1–10 tension score, a dominant emotion, and a read on native-language slang and nuance that keyword-based tools miss entirely.
  4. A transparent, five-parameter credibility grade. Every event is scored 0–100 across source reputation, cross-referencing, evidence level, contextual plausibility, and freshness — with the reasoning shown, not a black-box trust score.
  5. An autonomous harvester, not just a manual tool. An external scheduler runs the same search-grounded pipeline every three hours, unattended. An event is kept only if its source is a real article from GDELT or ReliefWeb, or one of Google's own search citations, stored as the publisher's address. Every harvest and its audit trail are saved to Firestore.
  6. A public live map, with the analysis behind a login. Anyone can browse recent events by time, region and category. The summary, credibility score, sentiment and satellite check are for registered users.

This is a personal research prototype, not a production intelligence product. When the model is unavailable, the app shows the data it already has and invents nothing. Built end-to-end (React, Express, Gemini API, Firestore), deployed to Cloud Run, with a monthly spending cap on every model call.

Personal AI Research

Crimes of the 1% — a structured, sourced database of financial crime and litigation among the ultra-wealthy

A database that catalogs corporate and executive-level financial crime — fraud, market manipulation, tax evasion, state capture — against the actual enforcement outcome on record: criminal conviction, settlement, deferred prosecution, or litigation still in progress. Built the same way as the OSINT tracker: solo, in Google AI Studio, testing whether an LLM can hold a large, sourced, structured dataset together instead of just summarizing text.

  1. Sourced by design, not by afterthought. Every case record carries one or more citations classified by document type — DOJ filing, SEC order, court judgment, EPA record, ICIJ archive — instead of a single unlabeled link.
  2. Beyond a dollar figure. Each entry converts a financial penalty into a systemic-impact score and the years a worker on an illustrative $10,000 a year would need to earn it. A companion inequality dashboard turns the dataset into charts by sector and crime type, plus a deep-time view of how far back in Earth's history that worker would have had to start.
  3. Two Gemini-powered lenses on the same data. An AI Fact-Finder modal answers ad-hoc questions against the dataset, and an AI Patterns modal surfaces cross-case trends — which sectors recur, which enforcement types are most common — the same "structured reasoning over messy real data" test as the OSINT build.
  4. A submission path, not a closed dataset. A case-submission form lets anyone add a new entry directly — published immediately with an "AI-generated, unreviewed" disclosure badge, so the dataset isn't limited to whatever I find on my own research pass.
  5. Amounts and sources that hold up. An AI-found case shows a penalty only when its source states one, and its source must name the company or person. A source that has gone dead says so instead of linking nowhere.

Early-stage research build — React, TypeScript and Firebase/Firestore, seeded with an initial dataset rather than a continuously fact-checked ledger. Treat individual case entries as a starting point for your own verification, not a settled record.

Side Project

Wirefront — a browser vector-tank shooter with live co-op, built together with Claude

A homage to 1980s vector-scope arcade combat games. Drive and fire across a wireframe battlefield against wave-based enemy tanks — the cannon points wherever the hull points, so aiming is driving. No installs, runs straight in the browser, keyboard or touch controls.

  1. Real hidden-line removal, not a wireframe shader. Three.js EdgesGeometry plus a void-colored occlusion fill, so solid faces hide whatever sits behind them — the look of a 1980s vector cabinet, done with today's rendering.
  2. Every sound synthesized, no audio files. Engine hum, cannon fire, and explosions generated live with the WebAudio API.
  3. A shared, append-only leaderboard. Firestore security rules validate the document shape on write and block updates or deletes outright, so a score can be added but never altered.
  4. Live co-op presence. Firebase Realtime Database puts everyone with the page open into one shared global room as a real ally tank, with join/leave comms and client-side collision between allies.

The single-player game and the co-op presence layer above are both live. A fully shared world — where every player fights the same enemies on the same wave — is the next phase, not yet built.

Side Project

Ripple Type — a WebGL text effect built after staring at a TV title card for thirty seconds

Type any word and it ripples outward in ink and dust — a homage to the title-card treatment in Pluribus, rebuilt from scratch by looking at the effect and asking how it would actually work, not from any production asset.

  1. The hatching is real displacement, not a filter. A hand-written GLSL fragment shader samples a procedural line pattern at a per-pixel radially-displaced UV, so the lines genuinely bend where the wave passes through.
  2. The background rings aren't drawn — they're the wave. A hashed per-cell dot field renders at a density driven by the same scalar ripple value used for the text displacement, so the concentric rings and the letter distortion come from one shared field.
  3. Two ripple layers, not one. A constant low-amplitude ambient wave keeps the text alive at rest; click anywhere to layer a stronger, decaying ripple on top.

Side Project

November Countdown — a macOS screensaver and wallpaper that counted down my last working days

A dark card over a drifting field of green, counting the days to the end of November 2026. The screensaver and the desktop picture share one renderer, so they cannot drift apart.

  1. macOS 26 no longer reads the per-user screensaver folder. A saver installed there is missing from the picker, with no error anywhere. The binary that loads legacy savers names only the system folder, so the installer puts it there.
  2. A third-party screensaver cannot be the live desktop. So the wallpaper is a still frame of the same scene, rendered per display and refreshed by a launchd agent every 30 minutes.
  3. Three silent traps, handled by the installer. The screensaver host keeps running the old code after a reinstall, System Settings builds its list only at launch, and an open Wallpaper pane writes a stale picture back.
